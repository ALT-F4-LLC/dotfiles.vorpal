Plain-text walkthrough (same 15 steps)
  1. Plan approval (human). Erik approves in conversation; the session runs docket run activate RUN-7.
  2. Activate (engine). Docket pins versions, binds pipelines, lints the DAG, expands DKT-101's steps, promotes; next returns the ready set.
  3. Relay (harness). The run skill opens a dispatch manifest and mirrors the ready set into the saved wave workflow; spawn-guard verifies the args (docket guard spawn), and next refuses to proceed past an unreconciled dispatch.
  4. Implement (LLM). A write-executor claims atomically, receives its assembled brief, works tests-first, records its change-summary artifact itself.
  5. Gates (engine). build, tests, scope, self-hygiene, secret-scan run and are recorded; routing to review is computed.
  6. Review fan-out (LLM). Four read-only judges in parallel emit findings — there is no verdict field.
  7. Synthesize (LLM). Duplicate findings are clustered across judges.
  8. Reconcile (engine). Median severity, held on ≥2 spread (a human gate only then), demotions recorded; thresholds route one high finding to a fix-loop.
  9. Fix (LLM). Repair against the reconciled findings; gates re-run; delta re-review; loop budget ≤2, then human.
  10. Verify-AC (LLM). Per-AC met/unmet/unverifiable with evidence, judged from the issue body alone.
  11. AC commands (engine). The ```ac```-fenced commands run literally; exits recorded.
  12. Commit authorization (human). The session shows the real diff; Erik approves in conversation and the session approves the gate.
  13. Commit (LLM + engine). commit-author drafts; commit-msg/commit-exec gates and the commit-guard hook execute it only behind the approval.
  14. DAG advances (engine). DKT-101 done unlocks DKT-102; write steps serialize in v1 ([limits] write=1) while read fan-outs stay parallel; waves repeat.
  15. Ledger (engine → human). The session runs docket run report and narrates it: cost, models requested vs resolved, gate trail, attempts — Erik judges the run (07 §4).
