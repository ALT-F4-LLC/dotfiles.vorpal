# SDET recurring pitfalls (in-repo)

- **Symptom:** a Bash tool call that embeds guard-hook test specimens inline (heredoc/echo args containing `git commit` / `git push` / `git add` text) is denied by the DEPLOYED guard-no-commit-hook before it runs, aborting the whole verification step — even though the call performs no git write. **Root cause:** the deployed PreToolUse hook scans the literal `.tool_input.command` string; specimen prose inside the command matches the write arm exactly as a real invocation would. Observed three independent times in the DKT-189 cycle (advisor, TDD author, this verifier). **Resolution:** route specimen corpora through files — Write the corpus (TSV/JSON) with the Write tool, have the harness read specimens from the file, and keep the Bash command string itself free of `git <write-verb>` bigrams. The hook's own documented file-and-path escape hatch is the sanctioned form of this.
